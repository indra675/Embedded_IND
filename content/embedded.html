Part A: Concepts in Detail

1. Embedded Systems Basics

An embedded system is a computer built into a device to do a dedicated job (washing machine controller, car ECU, pacemaker, smart meter). It usually has tight limits on memory, power, cost and timing.

  • Microcontroller (MCU): CPU, Flash, SRAM, and peripherals (GPIO, timers, ADC, UART, SPI, I2C) on one chip. Examples: AVR/ATmega, PIC, STM32 (ARM Cortex-M), ESP32, 8051.
  • Microprocessor (MPU): CPU only (or CPU with few extras); needs external RAM, storage and peripherals; usually runs Linux. Examples: Cortex-A, Raspberry Pi SoC.
  • Harvard vs von Neumann: Harvard has separate buses and memories for code and data (AVR, many DSPs, Cortex-M3/M4 internally); von Neumann shares one bus.
  • Memory types: Flash (non-volatile, holds code and constants, erased in blocks, limited write cycles), SRAM (volatile, fast, holds variables and stack), EEPROM (non-volatile, byte-erasable, slow), ROM (fixed at manufacture).
  • Bare metal vs RTOS: bare metal runs a super-loop plus interrupts; an RTOS (FreeRTOS, Zephyr, ThreadX) adds tasks, scheduling and synchronization.
  • Real-time: correctness depends on timing. Hard real-time: a missed deadline is a failure (airbag). Soft: occasional misses are tolerable (video playback). Key terms: determinism, latency, jitter, worst-case execution time (WCET).
  • Toolchain: cross-compiler (arm-none-eabi-gcc) builds on a PC for a different target; the linker script places code and data in the chip memory map; the map file shows what used how much memory; a programmer/debugger (ST-Link, J-Link) flashes the chip over JTAG or SWD.
  • Typical constraints: a few KB of RAM, no OS, no virtual memory, no file system, no heap (often), strict power budgets, and code that must run for years without reset.

2. Data Types, Endianness, Alignment

  • Use fixed-width types from <stdint.h>: uint8_t, int16_t, uint32_t, int64_t. Plain int is 16 bits on many 8/16-bit MCUs and 32 bits on ARM, so it is not portable.
  • Use uint8_t for bytes and register-sized values; use bool from <stdbool.h> for flags.
  • Endianness: little endian stores the least significant byte at the lowest address (ARM Cortex-M, x86, AVR). Big endian stores the most significant byte first (network byte order, some PowerPC/older MCUs). Convert when sending multi-byte values over a protocol that defines an order.
  • Alignment: a 32-bit value should sit at an address divisible by 4. Cortex-M0/M0+ fault on unaligned access; Cortex-M3 and above handle many unaligned accesses with extra cycles.
  • Struct padding: the compiler adds padding bytes for alignment. __attribute__((packed)) removes padding but may cause unaligned access. For protocol frames, prefer reading bytes into fields explicitly rather than casting a buffer to a struct.
  • Integer promotion: 8- and 16-bit values are promoted to int in expressions. Beware of ~(uint8_t value) producing a negative or large int; cast the result back.
  • Overflow: unsigned wraps (well defined); signed overflow is undefined.
  • Floating point: without an FPU (M0, M3, AVR) float math is done in slow software; prefer integers or fixed-point.

3. Bit Manipulation for Registers

Hardware is controlled by setting and clearing individual bits in registers. These patterns are used constantly.

#define BIT(n)            (1UL << (n))
#define SET_BIT(reg, n)   ((reg) |=  BIT(n))
#define CLR_BIT(reg, n)   ((reg) &= ~BIT(n))
#define TOG_BIT(reg, n)   ((reg) ^=  BIT(n))
#define READ_BIT(reg, n)  (((reg) >> (n)) & 1UL)
/* multi-bit field: set bits [pos+width-1 : pos] to value */
#define SET_FIELD(reg, pos, width, val) \
    ((reg) = ((reg) & ~(((1UL << (width)) - 1UL) << (pos))) | (((val) & ((1UL << (width)) - 1UL)) << (pos)))
  • Use 1UL (unsigned) so that shifting into bit 31 does not hit signed overflow.
  • Read-modify-write (reg |= mask) is not atomic. If an ISR modifies the same register between the read and the write, a change is lost. Prefer dedicated set/clear registers (for example STM32 BSRR) or disable interrupts around the update.
  • Bit-fields in structs are convenient but their bit order and packing are implementation-defined, so avoid them for hardware registers in portable code. Use masks and shifts.
  • Some registers are write-1-to-clear (interrupt flags): writing 1 clears the flag, so do not use read-modify-write on them.

4. volatile, const, static

  • volatile tells the compiler that a value can change outside the code it can see, so every access must really happen and must not be cached in a register or removed.
  • Use it for: memory-mapped peripheral registers, variables shared between an ISR and main code, and variables changed by hardware or another core.
  • It does not make operations atomic and does not replace a mutex or critical section. A 32-bit volatile counter read on an 8-bit MCU can still be torn.
volatile uint8_t data_ready = 0;      /* set in ISR, read in main */
void USART_IRQHandler(void) { data_ready = 1; }
int main(void) {
    while (!data_ready) { }           /* without volatile, compiler may loop forever */
    /* process data */
}
  • const volatile: read-only for your code but can change by itself, for example a status register or a hardware timer count: const volatile uint32_t *STATUS.
  • volatile uint8_t *p: pointer to volatile data. uint8_t *volatile p: the pointer itself is volatile.
  • const globals are placed in Flash (.rodata), saving RAM. Put lookup tables, strings and configuration in const arrays. On AVR (Harvard) Flash data needs special access (PROGMEM).
  • static local: persists across calls (stored in .data or .bss, not on the stack). static global/function: file-private; use it to limit visibility and avoid name clashes.
  • inline / static inline replace function-like macros when you want type checking with zero call overhead.

5. Memory-Mapped I/O and Registers

Peripherals appear as ordinary memory addresses. Writing to an address controls hardware; reading returns hardware state.

/* Direct address */
#define GPIOA_ODR   (*(volatile uint32_t *)0x48000014UL)
GPIOA_ODR |= (1UL << 5);              /* LED on pin 5 high */
/* Struct overlay (CMSIS style) */
typedef struct {
    volatile uint32_t MODER;   /* 0x00 mode           */
    volatile uint32_t OTYPER;  /* 0x04 output type    */
    volatile uint32_t OSPEEDR; /* 0x08 speed          */
    volatile uint32_t PUPDR;   /* 0x0C pull up/down   */
    volatile uint32_t IDR;     /* 0x10 input data     */
    volatile uint32_t ODR;     /* 0x14 output data    */
} GPIO_TypeDef;
#define GPIOA ((GPIO_TypeDef *)0x48000000UL)
GPIOA->MODER |= (1UL << (5 * 2));     /* pin 5 as output */
GPIOA->ODR   ^= (1UL << 5);           /* toggle LED      */
  • Steps to use any peripheral: enable its clock, configure pins (mode, pull, alternate function), configure the peripheral, enable interrupts if needed, then enable the peripheral.
  • Typical GPIO modes: input (floating, pull-up, pull-down), output push-pull, output open-drain, alternate function, analog.
  • A floating input picks up noise and reads random values; always use a pull-up or pull-down.
  • Push-pull drives both high and low. Open-drain only pulls low; an external pull-up makes the high level (used by I2C and for wired-AND buses).

6. Memory Layout, Startup and Linker

What happens from reset to main

  • The CPU loads the initial stack pointer from the first word of the vector table and jumps to the reset handler (the second word).
  • Reset_Handler (startup code) copies .data from Flash to RAM, zeroes .bss, calls SystemInit() (clock and basic setup), runs C library or C++ static initializers, then calls main().
  • If main() returns, the startup code usually enters an infinite loop. Embedded main() normally never returns.

Linker script

  • Defines memory regions (FLASH, RAM with origin and length) and places sections into them. Exports symbols such as _sdata, _edata, _sbss, _ebss, _estack used by startup code.
  • The map file shows the size and address of every symbol; use it to find what consumes Flash or RAM.

Stack and heap in embedded

  • Stack size is fixed by you. Overflow silently corrupts other memory or triggers a fault. Detect with stack painting (fill with a pattern and check the high-water mark), an MPU guard region, or RTOS stack checks.
  • Avoid recursion and large local arrays. Estimate worst-case stack depth including ISRs.
  • Avoid malloc/free in long-running firmware: fragmentation, non-deterministic timing, and allocation failure at runtime. Prefer static allocation or fixed-size memory pools. If allowed, allocate once at startup.
  • Flash writes: a bit can only be changed from 1 to 0 by programming; erasing (usually a whole page or sector) sets bits back to 1. Flash has a limited number of erase cycles, so use wear levelling for frequently changing data.

7. Interrupts

An interrupt is a hardware signal that makes the CPU pause the current code, run an Interrupt Service Routine (ISR), and then resume. It lets the system react to events without polling.

  • Vector table: an array of addresses of handlers, one per exception or interrupt source. The CPU fetches the handler address from it.
  • Priority: each interrupt has a priority. On Cortex-M, a lower number means higher priority. A higher-priority interrupt can preempt a lower one (nesting).
  • Latency: time from the event to the first ISR instruction. It is affected by the current instruction, interrupts being masked, higher-priority ISRs, and the context save (Cortex-M hardware stacks 8 registers automatically).

ISR rules

  • Keep ISRs short and fast: do the minimum (read data, clear the flag, set a variable or push to a queue) and do the rest in the main loop or a task.
  • Do not call blocking functions, delays, printf, malloc, or non-reentrant library functions inside an ISR.
  • Variables shared with the main code must be volatile and accessed atomically (protect with a critical section if larger than the native word size or modified in several steps).
  • Always clear the peripheral interrupt flag, or the ISR will fire again immediately.
  • ISRs take no arguments and return nothing; they cannot be called like normal functions.
  • Keep ISR stack usage low, since interrupts use the same stack (or the main stack on Cortex-M).

Critical sections

/* Cortex-M example using CMSIS */
uint32_t primask = __get_PRIMASK();
__disable_irq();
/* ... touch shared data ... */
__set_PRIMASK(primask);        /* restore previous state, do not blindly enable */
  • Keep critical sections as short as possible; long ones increase latency and can miss events.

8. Peripherals (GPIO, Timers, ADC, DMA, Watchdog)

GPIO and switch debouncing

  • Mechanical switches bounce for roughly 5 to 20 ms, producing multiple edges. Fix in hardware with an RC filter, or in software by requiring a stable reading for several samples or a fixed time.

Timers

  • A timer counts clock ticks. Frequency after the prescaler is f_timer = f_clk / (PSC + 1). Overflow/update period = (PSC + 1) x (ARR + 1) / f_clk.
  • Modes: basic periodic interrupt, input capture (measure pulse width or frequency), output compare, PWM, one-pulse, encoder mode.
  • PWM: a fixed-frequency square wave whose duty cycle (percent high) controls average power, for example LED brightness or motor speed. Duty = CCR / (ARR + 1).
  • SysTick (Cortex-M): a 24-bit down-counter used for the system tick (commonly 1 ms) and RTOS scheduling.

ADC

  • Converts an analog voltage to a digital number. Resolution is the number of bits (10-bit gives 1024 levels, 12-bit gives 4096).
  • Digital value = Vin / Vref x (2^N - 1). LSB size = Vref / 2^N. Example: 12-bit with 3.3 V gives about 0.8 mV per step.
  • Sampling rate must be at least twice the highest signal frequency (Nyquist). Add an anti-aliasing filter. Source impedance and sampling time affect accuracy. Averaging several samples reduces noise.

DMA

  • The DMA controller copies data between memory and peripherals (or memory to memory) without CPU involvement and raises an interrupt when done. Typical uses: ADC buffers, UART/SPI bulk transfers, display frame buffers. Use circular mode for continuous streams.

Watchdog timer

  • A counter that resets the MCU if the firmware fails to refresh ("kick") it within a timeout. It recovers from hangs and infinite loops. Kick it only from a place that proves the system is healthy, not from a timer ISR that keeps running while the main loop is stuck. A window watchdog also faults if kicked too early.

Low-power modes

  • Sleep, stop, standby (names vary). The CPU waits with WFI (wait for interrupt) or WFE. Wake sources: interrupts, RTC, external pin. Reduce power by lowering clock frequency, gating unused peripheral clocks, and sleeping between events.

9. Communication Protocols

UART (serial)

  • Asynchronous, two wires (TX, RX) plus ground, no shared clock. Both sides must agree on baud rate, data bits (usually 8), parity, and stop bits. The common setting is 8N1 (8 data bits, no parity, 1 stop bit).
  • Idle line is high; a frame starts with a start bit (low), then data (LSB first), optional parity, and stop bit(s) (high).
  • Point to point. TTL-level UART is not the same as RS-232 (higher voltages) or RS-485 (differential, multi-drop, long distance).
  • Receive with interrupts or DMA and a ring buffer to avoid losing bytes.

SPI

  • Synchronous, full duplex, four wires: SCK (clock), MOSI, MISO, and CS/SS (chip select, one per slave). The master generates the clock. No addressing: select a slave with its CS line.
  • Four modes from clock polarity (CPOL: idle level) and clock phase (CPHA: which edge samples data). Master and slave must use the same mode.
  • Fast (several MHz to tens of MHz), simple hardware, but more pins and no built-in acknowledgment.

I2C

  • Two wires: SDA (data) and SCL (clock), both open-drain with external pull-up resistors (commonly 2.2 to 10 kOhm). Multiple masters and slaves on one bus; each slave has a 7-bit (or 10-bit) address.
  • Transfer: START, address plus R/W bit, ACK from the slave, data bytes each followed by ACK/NACK, then STOP. Speeds: 100 kHz standard, 400 kHz fast, 1 MHz fast-plus.
  • Common problems: missing or wrong pull-ups, address confusion (7-bit address vs shifted 8-bit form), a slave holding SDA low (bus stuck; clock out nine pulses to recover), clock stretching.

CAN

  • Two-wire differential bus (CAN_H, CAN_L) with 120 Ohm termination at both ends. Multi-master, message-based: frames carry an identifier, not a destination address. Lower identifier wins arbitration without data loss. Built-in CRC, acknowledgment, and error handling. Used in automotive and industrial systems (up to 1 Mbps classic CAN, higher with CAN FD).

Others

  • USB, Ethernet, Bluetooth LE, Wi-Fi, LIN, Modbus, 1-Wire. Knowing what each is used for is usually enough for interviews.

10. Timing and Scheduling Approaches

  • Blocking delay loops waste CPU and are inaccurate. Prefer a hardware timer.
  • Non-blocking timing with a free-running tick counter:
static uint32_t last = 0;
if ((uint32_t)(millis() - last) >= 500U) {   /* safe across counter wrap-around */
    last = millis();
    toggle_led();
}
  • Super-loop (foreground/background): main loop runs tasks in order; ISRs handle urgent events. Simple, but one slow task delays all others.
  • Time-triggered / cooperative scheduler: a timer tick sets flags; the main loop runs tasks whose period has elapsed.
  • Finite state machine (FSM): model behavior as states and transitions; ideal for protocols, UI, and control logic. Implement with a switch on an enum or a table of function pointers.
  • RTOS: preemptive priority-based scheduling for hard deadlines and complex concurrency.

11. RTOS Concepts

  • Task (thread): an independent function with its own stack and priority. Task states: running, ready, blocked (waiting on delay/queue/semaphore), suspended.
  • Scheduler: chooses which ready task runs. Preemptive: a higher-priority task interrupts a lower one immediately. Cooperative: tasks yield voluntarily. Round robin shares CPU among equal-priority tasks via time slices.
  • Context switch: save the current task registers, load the next one. On Cortex-M it is done in the PendSV exception, with SysTick driving the tick.
  • Semaphore: a signaling counter. Binary semaphore signals an event (often ISR to task). Counting semaphore tracks resources or events.
  • Mutex: protects a shared resource; has an owner and only the owner unlocks it. Supports priority inheritance in most RTOSes.
  • Queue: thread-safe FIFO to pass data between tasks and from ISRs to tasks. Event flags/groups: wait on bit patterns. Software timers: callbacks driven by the tick.
  • Race condition: the result depends on the order in which tasks/ISRs access shared data. Fix with mutexes, critical sections, or message passing.
  • Deadlock: tasks wait on each other forever. It needs mutual exclusion, hold and wait, no preemption, and circular wait. Prevent by acquiring locks in a fixed order or using timeouts.
  • Priority inversion: a high-priority task is blocked by a low-priority task holding a mutex, while a medium-priority task preempts the low one. Solved by priority inheritance (the holder temporarily gets the blocked task priority) or priority ceiling.
  • Starvation: a low-priority task never runs because higher ones always do.
  • Reentrant function: safe if interrupted and called again, because it uses only local variables or protected shared state. Required for functions used by multiple tasks or ISRs.
  • Mutex vs binary semaphore: a mutex is for mutual exclusion with ownership and priority inheritance; a binary semaphore is for signaling between contexts, with no owner.
  • Never use a mutex in an ISR; use ISR-safe APIs such as xSemaphoreGiveFromISR and xQueueSendFromISR in FreeRTOS.

12. ARM Cortex-M Essentials

  • Registers: R0 to R12 (general), R13 (SP: MSP main stack pointer and PSP process stack pointer), R14 (LR link register), R15 (PC), and xPSR (status). Cortex-M executes Thumb/Thumb-2 instructions only.
  • Exception entry: hardware automatically pushes R0 to R3, R12, LR, PC, xPSR onto the stack, loads the handler address from the vector table, and sets LR to a special EXC_RETURN value. A return from the handler restores the context.
  • NVIC: the interrupt controller; handles enable/disable, pending, and priority for each interrupt.
  • Core exceptions: Reset, NMI, HardFault, MemManage, BusFault, UsageFault, SVCall, PendSV, SysTick.
  • HardFault causes: invalid memory access (null or wild pointer), unaligned access on cores that do not support it, executing an invalid instruction, calling a function through a bad pointer, stack overflow, divide by zero if trapping is enabled.
  • Variants: M0/M0+ (smallest, lowest power), M3, M4 (adds DSP and optional FPU), M7 (high performance), M23/M33 (TrustZone security).
  • MPU: memory protection unit; defines regions with access rights to catch stack overflows and isolate tasks.
  • Bit-banding (M3/M4): alias addresses allow atomic access to single bits in some memory regions.

13. Coding Practices (MISRA, Defensive Coding)

  • MISRA C is a safety and reliability coding standard widely used in automotive, medical and industrial software. Typical guidance: no dynamic memory allocation, no recursion, always use braces for if/else/loops, avoid implicit type conversions, initialize all variables, one statement per line, no unreachable code, and use fixed-width types.
  • Use named constants and enums, not magic numbers. Use static for file-private items. Keep functions small and single-purpose.
  • Check inputs and return codes; use assert (compiled out in release or routed to a safe handler) for invariants.
  • Fail safe: define what the device does on error (safe state, reset, error code), not just in the normal path.
  • Avoid global variables where possible; where needed, document who reads and writes them, especially across ISR and main.
  • Compile with warnings on (-Wall -Wextra) and use static analysis (cppcheck, clang-tidy, commercial MISRA checkers).
  • Version firmware, and store a version and CRC so the device can verify its own image.

14. Optimization for Small Devices

  • Choose appropriate types: use the smallest type that fits, but do not use types narrower than the native word in tight loops (it can add extra instructions).
  • Prefer integer and fixed-point arithmetic. A Q15 or Q31 number is an integer interpreted as value / 2^15 (or 2^31); multiply then shift right.
  • Replace division and modulo by powers of two with shifts and masks. Avoid division in hot code on cores without a hardware divider.
  • Use lookup tables in Flash for expensive functions (sine, CRC) when Flash is plentiful.
  • Compiler options: -Os for size, -O2 for speed. Enable -ffunction-sections -fdata-sections with linker --gc-sections to drop unused code.
  • Loop counting down to zero is slightly cheaper on some cores. Avoid passing large structs by value; pass pointers.
  • Use static inline for tiny functions. Measure first; verify with the map file and a profiler or cycle counter (DWT->CYCCNT on Cortex-M3 and above).
  • Keep strings and tables in Flash; avoid printf with floating point on small MCUs (large code and stack use). Use a light formatting routine.

15. Bootloaders and Firmware Updates

  • A bootloader is a small program at the start of Flash that runs first, checks whether an update is requested or the application is valid (CRC or signature), and then jumps to the application.
  • To jump to the application: read its initial stack pointer and reset vector from the application vector table, set the vector table offset (SCB->VTOR), set MSP, and branch to the reset handler.
  • The application is linked at a different Flash origin (after the bootloader), so the linker script must match.
  • Update channels: UART, USB, CAN, SPI/I2C, over-the-air (OTA) via Wi-Fi or Bluetooth. Safer designs keep two application slots (A/B) and roll back if the new image fails to boot.
  • Protect updates with CRC for integrity and cryptographic signatures for authenticity.

16. Debugging

  • JTAG/SWD with an on-chip debugger (ST-Link, J-Link) gives breakpoints, single-step, register and memory view, and flash programming. SWD uses two pins.
  • printf debugging over UART or semihosting/ITM (SWO) is useful but changes timing.
  • Logic analyzer decodes UART, SPI, I2C and shows timing; an oscilloscope shows signal quality (voltage levels, ringing, edges).
  • HardFault debugging: inspect the stacked PC and LR from the fault handler to find the instruction that caused the fault; check the fault status registers (CFSR, HFSR, BFAR, MMFAR).
  • Use GPIO toggling plus a scope to measure ISR duration and latency.
  • Typical bug sources: missing volatile, uninitialized variables, stack overflow, race between ISR and main, wrong clock setup, incorrect register bit positions, I2C pull-ups, and misunderstood timing.

17. Interview Questions with Answers

What is an embedded system? A dedicated computing system built into a larger device, performing specific functions with constraints on memory, power, cost, and timing.

MCU vs MPU? An MCU integrates CPU, memory and peripherals on one chip and usually runs bare metal or an RTOS. An MPU needs external memory and peripherals and typically runs a full OS such as Linux.

Why is volatile important in embedded C? It prevents the compiler from optimizing away or reordering accesses to values that change outside program flow: hardware registers, ISR-shared variables.

Can a variable be both const and volatile? Yes. const volatile means your code cannot write it but hardware can change it, such as a read-only status register.

Can a pointer be volatile? Yes: int *volatile p means the pointer value can change unexpectedly; volatile int *p means the pointed-to data can.

Is volatile enough for thread safety? No. It only controls compiler optimization. Use critical sections, mutexes, or atomic operations for multi-step or multi-word access.

What is an ISR and what are its rules? A function the hardware calls on an interrupt. Keep it short, no blocking calls, clear the flag, use volatile for shared data, avoid non-reentrant and heavy library calls.

Can an ISR return a value or take parameters? No. It is called by hardware, not by your code.

What is interrupt latency? The time between the interrupt request and the start of the ISR. It depends on masked interrupts, higher-priority ISRs, the current instruction, and context save.

What is a vector table? A table of handler addresses indexed by exception number; the CPU reads it to find the ISR.

What is the difference between polling and interrupts? Polling repeatedly checks status in software; interrupts let hardware notify the CPU when an event occurs.

What is DMA? Hardware that transfers data between peripherals and memory without CPU involvement.

What is a watchdog timer? A timer that resets the system if software does not refresh it in time, recovering from hangs.

Where do local, global, static and const variables live? Locals on the stack; initialized globals/statics in .data; uninitialized in .bss; const data in Flash (.rodata); dynamic data on the heap.

What is the difference between .data and .bss? .data holds explicitly initialized variables and needs an initial image in Flash copied to RAM at startup; .bss holds zero-initialized ones and is simply cleared.

What happens when the microcontroller resets? The CPU loads SP and the reset vector, runs the startup code to copy .data, zero .bss and set up clocks, and then calls main.

Why avoid malloc in embedded systems? Fragmentation, non-deterministic execution time, possible allocation failure, and extra code and RAM. Use static allocation or memory pools.

What is stack overflow and how do you detect it? The stack grows into other memory. Detect with stack painting, MPU guard regions, RTOS checks, or fault handlers.

How do you set, clear, toggle, and test a bit? Set: reg |= (1U << n). Clear: reg &= ~(1U << n). Toggle: reg ^= (1U << n). Test: (reg >> n) & 1U.

How do you check endianness? uint16_t x = 1; *(uint8_t *)&x == 1 means little endian.

What is struct padding and how do you avoid wasted space? Padding aligns members. Order members from largest to smallest, or use packed (accepting unaligned access cost).

UART vs SPI vs I2C? UART: async, 2 wires, point to point. SPI: sync, 4 wires, fast, full duplex, chip select per slave. I2C: sync, 2 wires, addressable multi-device, slower, needs pull-ups.

Why does I2C need pull-up resistors? Its lines are open-drain; devices can only pull the line low, so resistors create the high level.

What are SPI modes? Four combinations of CPOL (idle clock level) and CPHA (sampling edge); master and slave must match.

What is baud rate? Symbols per second on a serial line; for UART, roughly bits per second including start and stop bits.

How does CAN arbitration work? Nodes transmit identifiers bit by bit; a dominant (0) bit overrides recessive (1), so the lowest identifier wins without corrupting data.

What is debouncing? Filtering the multiple transitions of a mechanical switch, in hardware (RC) or software (time or sample counting).

What is PWM and its uses? A fixed-frequency signal with adjustable duty cycle to control average power: LED dimming, motor speed, DAC approximation.

Mutex vs semaphore? A mutex is owned and used for mutual exclusion (with priority inheritance); a semaphore is a signaling or counting mechanism with no owner.

What is priority inversion? A high-priority task waits on a resource held by a low-priority task that is preempted by a medium-priority one. Fix with priority inheritance or ceiling.

What is a deadlock and how can you avoid it? Tasks waiting on each other forever. Avoid with consistent lock ordering, timeouts, and minimal locking.

What is a race condition? Behavior depends on the timing of concurrent accesses. Protect shared data with critical sections or mutexes.

What is a reentrant function? It can be safely interrupted and called again; it uses no static or global state unless protected.

What is a context switch? Saving the running task state and restoring another task state so it can run.

Super-loop vs RTOS? A super-loop is simple and deterministic for small systems; an RTOS gives scheduling, priorities, and synchronization for complex or time-critical systems at the cost of memory and overhead.

What is a bootloader? A small program that starts first, validates and loads or updates the application, then jumps to it.

Why use fixed-width integer types? Plain int size varies across compilers and architectures; fixed-width types make code portable and register-accurate.

What is the purpose of a linker script? To define memory regions and place code and data sections at the right addresses for the target.

What causes a HardFault on Cortex-M? Invalid memory or peripheral access, unaligned access on cores that forbid it, undefined instructions, bad function pointers, stack corruption, and divide by zero if enabled.

How do you reduce power consumption? Lower clock speed, sleep modes (WFI), turn off unused peripherals, wake on interrupts, and reduce active time.

What is the difference between a compiler and a cross-compiler? A cross-compiler runs on a host machine (PC) but produces code for a different target architecture such as ARM Cortex-M.

What is the difference between Flash and EEPROM? Flash erases in blocks and is used for code; EEPROM allows byte-level erase/write and is used for small persistent data. Both have limited write endurance.

2. Count set bits

uint8_t count_bits(uint32_t x) {

3. Reverse the bits of a byte

uint8_t reverse_bits(uint8_t b) {
    b = (uint8_t)(((b & 0xF0U) >> 4) | ((b & 0x0FU) << 4));
    b = (uint8_t)(((b & 0xCCU) >> 2) | ((b & 0x33U) << 2));
    b = (uint8_t)(((b & 0xAAU) >> 1) | ((b & 0x55U) << 1));
    return b;
}

4. Swap nibbles and swap endianness

uint8_t swap_nibbles(uint8_t b) { return (uint8_t)((b << 4) | (b >> 4)); }
uint32_t swap32(uint32_t x) {
    return ((x & 0x000000FFUL) << 24) |
           ((x & 0x0000FF00UL) <<  8) |
           ((x & 0x00FF0000UL) >>  8) |
           ((x & 0xFF000000UL) >> 24);
}

5. Check endianness

int is_little_endian(void) {
    uint16_t x = 1;

}

6. Check if a number is a power of two

int is_pow2(uint32_t x) { return x && !(x & (x - 1U)); }

7. Circular (ring) buffer

#define BUF_SIZE 64U               /* power of two makes wrap cheap */
typedef struct {
    uint8_t buf[BUF_SIZE];
    volatile uint16_t head;        /* written by producer (ISR)   */
    volatile uint16_t tail;        /* written by consumer (main)  */
} RingBuf;
int rb_put(RingBuf *rb, uint8_t v) {
    uint16_t next = (uint16_t)((rb->head + 1U) & (BUF_SIZE - 1U));
    if (next == rb->tail) return -1;       /* full */
    rb->buf[rb->head] = v;
    rb->head = next;
    return 0;
}
int rb_get(RingBuf *rb, uint8_t *v) {
    if (rb->head == rb->tail) return -1;   /* empty */
    *v = rb->buf[rb->tail];
    rb->tail = (uint16_t)((rb->tail + 1U) & (BUF_SIZE - 1U));
    return 0;
}

With a single producer (ISR) and a single consumer (main), this works without locks because each index is written by only one side. One slot is kept empty to distinguish full from empty.

8. Switch debounce (sample counting)

/* call every 1 ms */
#define DEBOUNCE_MS 20U
bool debounced_state = false;
void debounce_tick(bool raw) {
    static uint8_t count = 0;
    if (raw == debounced_state) { count = 0; return; }
    if (++count >= DEBOUNCE_MS) { debounced_state = raw; count = 0; }
}

9. Finite state machine

typedef enum { ST_IDLE, ST_RUNNING, ST_ERROR } State;
State step(State s, bool start, bool stop, bool fault) {
    switch (s) {
    case ST_IDLE:    return start ? ST_RUNNING : ST_IDLE;
    case ST_RUNNING: if (fault) return ST_ERROR;
                     return stop ? ST_IDLE : ST_RUNNING;
    case ST_ERROR:   return stop ? ST_IDLE : ST_ERROR;   /* stop acts as reset */
    default:         return ST_ERROR;
    }
}

10. memcpy and memset

void *my_memcpy(void *dst, const void *src, size_t n) {
    uint8_t *d = dst; const uint8_t *s = src;
    while (n--) *d++ = *s++;
    return dst;
}
void *my_memset(void *p, int v, size_t n) {
    uint8_t *d = p;
    while (n--) *d++ = (uint8_t)v;
    return p;
}

11. CRC-8 (polynomial 0x07)

uint8_t crc8(const uint8_t *data, size_t len) {
    uint8_t crc = 0x00;
    while (len--) {
        crc ^= *data++;
        for (uint8_t i = 0; i < 8; i++)
            crc = (crc & 0x80U) ? (uint8_t)((crc << 1) ^ 0x07U) : (uint8_t)(crc << 1);
    }
    return crc;
}

12. Fixed-point (Q15) multiply

typedef int16_t q15_t;             /* value = raw / 32768 */
q15_t q15_mul(q15_t a, q15_t b) {
    int32_t p = (int32_t)a * (int32_t)b;   /* Q30 */
    return (q15_t)(p >> 15);               /* back to Q15 */
}

13. LED toggle with button using registers (concept)

int main(void) {
    clock_enable_gpioa();                  /* 1. enable peripheral clock    */
    GPIOA->MODER |= (1UL << (5 * 2));      /* 2. PA5 output (LED)           */
    /* PA0 stays input with pull-down configured in PUPDR */
    for (;;) {
        if (GPIOA->IDR & (1UL << 0)) {     /* 3. button pressed?            */
            GPIOA->ODR ^= (1UL << 5);      /* 4. toggle LED                 */
            delay_ms(200);                 /*    crude debounce             */
        }
    }
}

14. Interrupt flag pattern (ISR sets flag, main handles it)

static volatile bool rx_flag = false;
static volatile uint8_t rx_byte;
void USART1_IRQHandler(void) {
    if (USART1->ISR & USART_ISR_RXNE) {
        rx_byte = (uint8_t)USART1->RDR;    /* reading RDR clears RXNE */
        rx_flag = true;

}
int main(void) {
    for (;;) {
        if (rx_flag) {
            rx_flag = false;
            process(rx_byte);
        }
    }
}
